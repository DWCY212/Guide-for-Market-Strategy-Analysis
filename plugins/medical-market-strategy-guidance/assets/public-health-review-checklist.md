# 公共卫生智能流调市场审查清单

本清单把公共卫生智能流调报告中的审查结论抽象为可复用规则。报告中的数字、客户反馈和项目判断仍需在实际研究中重新核验。

## 市场分支

| 分支 | 核心问题 | 不能直接外推 |
| --- | --- | --- |
| 传染病个案、聚集性和暴发调查 | 任务分派、调查执行、专业追问、质控、回写和归档是否闭环 | 疾控机构数量等于采购客户 |
| 常态及专项调查 | 任务是否有独立预算、采购包、验收和持续使用 | 任何调查任务都属于核心流调市场 |
| 省市疾控平台能力建设 | 上位平台与专业子系统的接口、权限、数据和责任边界 | 上位平台总金额等于智能流调子系统市场 |
| 电话调查辅助 | 接听、脚本、人工接管、质控和数据回写是否满足专业调查 | 通用外呼能力等于疾控流调产品 |
| 现场采集和终端协同 | 弱网、离线、终端管理、同步、审计和高峰扩容是否可用 | 流调人员数量等于终端采购数量 |

慢病危险因素、学生健康、烟草、职业健康和食品安全等邻接任务必须单独建立预算和采购证据，不能与核心市场合并计数。

## 客户购买链

每个项目至少填写：

| 角色 | 需要确认 |
| --- | --- |
| 任务发起者 | 谁定义调查任务、优先级和调查表 |
| 实际使用者 | 谁执行电话或现场调查，是否需要人工接管 |
| 专业审核者 | 谁审核追问、字段完整性、异常和质控退回 |
| 系统验收者 | 谁确认接口、权限、并发、日志和回写结果 |
| 付款者 | 预算属于疾控、卫健、专项任务还是集成项目 |
| 责任承担者 | 模型错误、漏项、误报和数据泄露由谁复核和处置 |

## 业务闭环和验收

至少验证：`任务接收 → 分派 → 调查执行 → 人工接管 → 专业质控 → 结果回写 → 归档`。

验收指标应绑定项目基线，至少考虑：调查完成率、字段完整率、漏项率、质控退回率、报告时效、人工接管率、接口成功率、离线恢复时间、并发能力、峰值扩容时间、方言/术语适配和审计日志完整性。演示功能、模型准确率或试运行反馈不能替代真实项目验收。

## 证据链和市场空间

按以下链条组织证据：

`机构基础盘 → 业务任务池 → 公开采购/预算 → 可采购产品包 → 公司目标名单 → 收入目标`

每条采购记录至少保留官方公告、预算、合同或验收链接，拆分软件、接口、实施、硬件、运营和总包金额。3.6 万台终端、若干部署节点、一体机数量或内部满配货值，若依赖配置率、单价、并发或覆盖假设，只能作为情景模型，不能直接命名为 TAM、SAM 或收入预测。

## 复制和交付经济性

分别建立省级、市级、县区级部署模型：实施人月、硬件、算力、接口适配、知识/规则配置、培训、运维、人工接管、毛利和续费。至少在两个差异明显地区记录模板复用率、接口复用率、方言适配工时、实施周期和新增成本。一个项目成功不能自动证明全国低成本复制。

## 竞争边界

按公司/供应商、产品模块、上位平台入口、采购项目、部署区域、价格/金额、交付案例和未知项建立矩阵。区分疾控平台厂商、医疗 AI 厂商、运营商、总集成商、人工调查和传统终端。没有公开证据时使用“当前公开材料未发现”或“待核验”，不要写成竞品没有能力。

## 成熟度门槛

缺少采购台账、完整调查闭环、客户预算/验收证据或交付经济性模型时，最高判为 M1“客群筛选”。至少一个真实项目闭环、三个区域客户的付费/验收确认和两个差异地区的复制数据，才可考虑进入 M2“进入设计”。
